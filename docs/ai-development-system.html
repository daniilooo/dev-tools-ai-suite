Fluxo de contexto

Contexto mínimo suficiente vale mais que contexto máximo disponível. Nenhum agente recebe o histórico inteiro da conversa.

Agentes

Um catálogo enxuto, sem agentes criados só para parecer sofisticado. O papel de PO e Tech Lead fica com o humano.

Orchestrator Tier 2

Classifica, decompõe, paraleliza, consolida, protege escopo e gates, atualiza o estado.

Explorer Tier 1

Perguntas factuais com referências. Não decide nem edita. Pode ter várias instâncias.

Reporter Tier 1

Relatórios para dev, tech lead, PO, gestor e daily. Nunca inventa números.

Architect Tier 2 Tier 3

Solução proporcional, ADRs, preserva os limites dos módulos.

backend-developer Tier 2

Node, Fastify, node-pty, SQLite.

frontend-developer Tier 2

Angular, Tailwind, xterm.js, design system.

DevOps Tier 2

CI, empacotamento npm, prebuilds, doctor, rollback.

QA Tier 1 Tier 2

Vitest e Playwright. Paralelizável: API, frontend, segurança, terminal.

Reviewer Tier 2

Bugs, regressões, invariantes, testes ausentes. Achados bloqueantes impedem o merge.

Security Engineer Tier 3

Obrigatório em auth, WebSocket, PTY, Origin, segredos e privacidade.

Skills e hooks

Skills portáveis

A lógica fica em .ai/skills/. Os wrappers em .claude/skills e .agents/skills apenas apontam para ela.

commit git-flow code-review testing documentation release architecture-decision security-review dependency-update

Hooks determinísticos

Ficam em .githooks/ e são ativados com git config core.hooksPath .githooks.

pre-commit: segredos, Prettier, ESLint (< 10 s)
pre-push: bloqueia push em main; typecheck, testes, build, validação
CI: lint → typecheck → unit → integration → build → security → E2E

Os commits seguem Conventional Commits com descrição em PT-BR, por exemplo feat(terminal): adiciona reconexão de sessão.

Gates humanos

O agente apresenta justificativa, impacto, riscos e rollback entre HUMAN_GATE_START e HUMAN_GATE_END. Silêncio não conta como aprovação.

  • HG-01Merge em main
  • HG-02Releases e tags oficiais
  • HG-03Publicação no npm
  • HG-04Mudança arquitetural ou de ADR aceito
  • HG-05Segurança do Core
  • HG-06Auth, WebSocket e controle de PTY
  • HG-07Dependências nativas críticas
  • HG-08Privacidade, indexação e transmissão
  • HG-09Exclusão de dados de usuários
  • HG-10Alterações destrutivas de banco
  • HG-11Permissões e segredos do GitHub
  • HG-12Exposição na rede ou internet
  • HG-13Envio de código a provedores externos
  • HG-14Iniciar nova fase
  • HG-15Ampliar o escopo do MVP

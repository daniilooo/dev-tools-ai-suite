# INTAKE

Usado no início do projeto (concluído — ver `vault/10_DECISIONS/INTAKE_RECORD.md`) e, em versão curta, para demandas estruturais.

## Intake curto para demanda estrutural

Perguntar ao humano **somente** o que altera produto, arquitetura, segurança, custo ou prazo:

1. Qual problema concreto a mudança resolve?
2. Qual critério objetivo indica que está pronta?
3. Afeta alguma invariante ou gate humano?
4. Pertence ao MVP ou ao pós-MVP?

Lacunas não críticas → recomendação pragmática registrada como **hipótese** no Vault.

Perguntas em blocos pequenos; nunca dezenas de perguntas de uma vez.
